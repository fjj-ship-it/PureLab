为什么要有状态栏

App 的 targetSdkVersion=35，在 Android 15+ 会被强制 edge-to-edge： 状态栏叠在内容之上。此时 App 顶部导航实际从 --safe-t 之下开始。 浏览器里预览看不到这层，外壳把状态栏画出来才能暴露「标题被时钟压住」这类问题。
这里开关状态栏时，会同步向 iframe 注入 --safe-t / --safe-b，等效于真机返回的 env(safe-area-inset-*)。

怎么用

  • 屏幕里可以直接点、直接输入，和真机一样。
  • 顶部下拉可直跳任意界面；在屏幕里自己点着走，左上角选择器会跟着变。
  • 软键盘勾上后，视口会像 adjustResize 那样缩短，用来验证输入框会不会被挡住。
  • 触达框会把可点元素描边：绿色 ≥44px，红色不足 44px，鼠标悬停能看到「可视尺寸 / 命中区尺寸」。判定用的是有效命中区（含 ::after 外扩量），不是元素盒；96 个孔位是已知物理约束，用琥珀色虚线单独标出、不计入「不足」统计。
  • 数据存在浏览器 localStorage，与手机上的数据互不影响；「重置数据」回到演示状态。
  • 应用锁定竖屏，所以这里不做横屏预览。

为什么不用起服务

本页是自包含单文件：App 的 index.html + app.css + app.js 已被内联、base64 编码后写在本页里，用 srcdoc 装进手机屏幕。 srcdoc 的文档天然与父页同源，所以跳屏、安全区注入、触达框都能用 —— WorkBuddy 侧边栏预览、直接双击打开、挂到 http 上都行，不必起本地服务。

改完 App 源码之后

预览页里用的是生成时的快照。改完 app/assets/www/ 下的文件后， 重跑一次 python build_preview.py，它会把最新的 HTML/CSS/JS 重新打进本页。

快捷键

Alt + ← / → 切上下界面 · Alt + R 重载 · Alt + 0 自适应缩放

出问题了？

顶部出现红色提示条 = 预览环境不允许脚本访问屏幕内的文档。 本页用 srcdoc 装载，正常应同源；若真被拦，把 preview.html 放到本地 http 下打开即可（同源规则会放行）。
